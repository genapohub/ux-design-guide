## 一、场景识别

### 场景识别决策表

| 场景 | 名称 | 判断条件（满足任一） | 产出量 | 预估周期 |
|------|------|---------------------|--------|---------|
| 场景一 | 0→1 新产品设计 | 全新产品线、无现有设计系统、需从用户研究开始、涉及全端设计(iOS/Android/Web)、需定义设计语言 | 10-12类 | 2-4周 |
| 场景二 | 中大型功能迭代 | 已有产品新增模块、涉及3+页面/多角色、需交互设计+视觉设计、需设计评审 | 6-8类 | 1-2周 |
| 场景三 | 小优化/微调 | 单页面调整、文案/间距/颜色微调、不涉及交互变更、无需评审 | 2-3类 | 1-3天 |
| 场景四 | 设计系统大版本升级 | 设计语言迭代(如Material→自研)、组件库大版本、涉及Breaking Change、影响全局 | 8-10类 | 3-6周 |
| 场景五 | 概念探索/预研 | 业务方向未定、需设计探索验证、竞品UX分析、可能不落地 | 3-4类 | 1-2周 |

### 识别流程（决策树）

```
是否全新产品/无设计基础？ → 是 → 场景一
    ↓否
是否为设计系统大版本升级？ → 是 → 场景四
    ↓否
是否为方向探索/概念方案？ → 是 → 场景五
    ↓否
是否涉及3+页面/多角色/交互流程变化？ → 是 → 场景二
    ↓否
→ 场景三
```

## 二、场景一：0→1 新产品设计（12类产出）

### 调研阶段
1. **用户研究报告** — 目标用户画像、用户旅程地图、痛点与需求分析
2. **竞品UX分析报告** — 直接竞品+间接竞品的设计语言、交互模式、信息架构对比
3. **设计趋势与环境分析** — 行业设计规范（如iOS HIG/Material Design）、视觉风格趋势

### 规划阶段
4. **信息架构设计** — 站点地图/应用架构图、导航层级、内容分类体系
5. **Design Token定义** — 颜色体系(主色/辅色/中性/语义色)、字体体系(层级/行高/字重)、间距体系(4pt/8pt栅格)、圆角/阴影/动效参数
6. **组件库规划** — 原子设计方法论（Atoms→Molecules→Organisms→Templates→Pages）、组件清单与优先级、变体(variant)定义

### 设计阶段
7. **交互设计规范** — 全局交互模式（导航/返回/手势/键盘）、页面转场动画、反馈机制（Loading/Toast/确认弹窗）、错误状态处理
8. **高保真设计稿** — 关键页面(首页/核心流程/设置/空状态)、多端适配方案（iOS/Android/Web/小程序）
9. **可交互原型** — 核心流程可点击原型、用户测试用原型
10. **无障碍设计规范** — WCAG 2.1 AA标准、色对比度检查、屏幕阅读器适配、焦点管理、触控区域最小尺寸

### 落地阶段
11. **设计标注与交付规范** — 切图规范(@2x/@3x/矢量)、标注文档(间距/颜色/字体/状态)、组件命名规范、Figma/Sketch组织规范
12. **设计走查清单** — 开发还原度检查表、各端适配检查表、交互状态覆盖检查表(default/hover/active/disabled/error/empty/loading)

## 三、场景二：中大型功能迭代（6-8类产出）

1. **需求理解文档** — 功能背景、用户场景、业务目标
2. **交互流程图** — 用户操作路径、主流程+异常分支+边界条件、页面跳转关系
3. **线框图/低保真原型** — 页面布局、内容优先级、信息层级
4. **高保真Mockup** — 关键页面视觉稿、各状态覆盖
5. **交互说明文档** — 每个交互元素的输入/反馈/状态、动画参数、手势定义
6. **设计标注** — 颜色/字体/间距/组件标注
7. **变更影响范围分析** — 受影响的其他页面/组件、需同步更新的设计文档
8. **走查清单** — 还原度检查、多端适配、异常状态覆盖

---

## 四、场景三：小优化/微调（2-3类产出）

1. **问题描述与优化方案** — 当前问题(附截图)、优化目标、改动说明
2. **标注截图** — 修改前/修改后对比，具体改动标注(颜色值/间距值/字号等)
3. **变更记录** — 更新设计文件位置、通知相关开发

---

## 五、场景四：设计系统大版本升级（8-10类产出）

1. **升级评估报告** — 升级动机、现有系统痛点分析、升级目标与预期收益
2. **差异分析** — 新旧Design Token对照表、组件API Breaking Changes清单、视觉风格差异对比
3. **迁移方案** — 渐进式迁移策略(分模块/分阶段)、旧版兼容方案、并行运行方案
4. **新版Design Token文档** — 完整Token定义、命名规范、使用场景
5. **新版组件库文档** — 每个组件的API/变体/状态/用法、迁移指南(旧→新)
6. **视觉回归测试方案** — 截图对比流程、自动化测试配置、关键页面检查清单
7. **变更日志** — 完整的Breaking Change列表、废弃警告、迁移时间线
8. **团队培训材料** — Slide/录屏/FAQ、迁移Workshop计划
9. **存量项目升级计划** — 各项目升级优先级、依赖关系、排期
10. **走查清单** — 升级后验证、多端验证、性能回归

---

## 六、场景五：概念探索/预研（3-4类产出）

1. **探索背景文档** — 业务问题/机会描述、探索目标
2. **Mood Board（情绪板）** — 2-3套风格方向、配色/字体/质感参考、设计关键词
3. **概念方案** — 2-3个核心页面概念稿、可行性分析(技术/资源/时间)
4. **竞品UX分析** — 关键竞品的交互模式、视觉风格、优劣势对比

## 七、通用设计交付标准

### 设计稿规范
- 命名规范：`{模块}_{页面/组件}_{状态}_{版本}`，如 `Home_Banner_Default_v2`
- Figma组织：Pages（探索/设计稿/标注/组件库/归档）
- 版本管理：大版本用 `.v1/.v2`，小迭代用日期 `_240722`
- 组件化：相同元素必须做成Component，使用Auto Layout，使用Style/Token

### 标注要求
- 颜色：标注色值 + 使用场景（如 `#1A1A2E / Brand Primary`）
- 字体：标注字号 + 行高 + 字重 + 使用场景
- 间距：标注水平/垂直间距（相对父容器或相邻元素）
- 状态：每个交互元素覆盖 default / hover / active / disabled / error / empty / loading
- 适配：标注响应式断点、弹性布局规则

### 交互状态覆盖清单
每个交互元素必须覆盖且标注以下状态：

| 状态 | 说明 | 必须覆盖 |
|------|------|:--:|
| Default | 默认/初始状态 | ✅ |
| Hover | 鼠标悬停（Web/Desktop） | ✅ |
| Active/Pressed | 按下/点击中 | ✅ |
| Disabled | 不可用状态 | ✅ |
| Focus | 键盘焦点（无障碍） | ✅ |
| Error | 错误提示状态 | ✅ |
| Empty | 无数据/空内容 | ✅ |
| Loading | 加载中/骨架屏 | ✅ |
| Success | 操作成功反馈 | ✅ |

### 无障碍最低要求（WCAG 2.1 AA）
- 色对比度：正文 ≥ 4.5:1，大字 ≥ 3:1，UI组件 ≥ 3:1
- 触控区域：最小 44×44pt（iOS）/ 48×48dp（Android）
- 焦点管理：Tab键可遍历所有可交互元素
- 屏幕阅读器：图片有alt文本，表单有label，状态变化有announcement
- 不依赖颜色传达信息：错误状态同时使用图标+颜色+文本

### 设备适配标准
| 平台 | 最小支持 | 设计基准 |
|------|---------|---------|
| iOS | iPhone SE → Pro Max | iPhone 14/15 (390×844) |
| Android | 360dp → 414dp | 390dp (hdpi→xxxhdpi) |
| Web | 320px → 1920px | 375px(移动)/768px(平板)/1440px(桌面) |
| 小程序 | 微信/支付宝/抖音 | 375px |

## 八、AI 工具使用建议

### 设计阶段建议使用的 AI 工具
| 阶段 | 推荐工具 | 用途 |
|------|---------|------|
| 用户研究 | AI对话分析 | 整理访谈记录、提炼用户画像 |
| 竞品分析 | AI网页抓取 | 收集竞品设计特征 |
| Wireframe | AI生成 | 快速生成线框图方案 |
| 视觉设计 | Figma AI插件 | 配色建议、图标生成、文案填充 |
| 原型 | AI生成代码 | HTML/CSS快速原型 |
| 标注 | Figma Dev Mode | 自动标注 |
| 走查 | AI对比 | 设计稿vs开发实现对比 |

### 常用提示词模板
```
我需要设计一个[产品类型]的[功能模块]，目标用户是[用户画像]。
请帮我：
1. 分析3个竞品的同类功能设计
2. 输出该功能的交互流程（含异常分支）
3. 输出关键页面的布局建议
```

## 九、产出质量检查清单

### 通用检查
- [ ] 场景判断正确，已与需求方确认
- [ ] 产出清单完整（必备文档全部生成）
- [ ] 设计稿命名与组织符合规范
- [ ] 各状态覆盖完整（default/hover/active/disabled/error/empty/loading）

### 交互检查
- [ ] 主流程清晰，无死胡同
- [ ] 异常/错误/空/加载状态有对应设计
- [ ] 关键操作有确认/撤销机制
- [ ] 符合平台交互规范（iOS HIG / Material Design）

### 视觉检查
- [ ] 颜色对比度达标（WCAG AA）
- [ ] 字体层级清晰（不超过4级）
- [ ] 间距一致（遵循栅格系统）
- [ ] 暗色模式适配（如需要）

### 标注检查
- [ ] 标注信息完整（颜色/字体/间距/状态/适配）
- [ ] 切图尺寸与格式正确
- [ ] 组件命名清晰、便于开发查找

### 无障碍检查
- [ ] 色对比度达标
- [ ] 触控区域达标
- [ ] 焦点顺序合理
- [ ] 不依赖颜色传达信息
