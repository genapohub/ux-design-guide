## 一、场景识别

### 场景识别决策表

| 场景 | 名称 | 判断条件（满足任一） | 产出量 | 预估周期 |
|------|------|---------------------|--------|---------|
| 场景一 | 0→1 新产品设计 | 全新产品线、无现有设计系统、需从用户研究开始、涉及全端设计(iOS/Android/Web)、需定义设计语言 | 10-12类 | 2-4周 |
| 场景二 | 中大型功能迭代 | 已有产品新增模块、涉及3+页面/多角色、需交互设计+视觉设计、需设计评审 | 6-8类 | 1-2周 |
| 场景三 | 小优化/微调 | 单页面调整、文案/间距/颜色微调、不涉及交互变更、无需评审 | 2-3类 | 1-3天 |
| 场景四 | 设计系统大版本升级 | 设计语言迭代(如Material→自研)、组件库大版本、涉及Breaking Change、影响全局 | 8-10类 | 3-6周 |
| 场景五 | 概念探索/预研 | 业务方向未定、需设计探索验证、竞品UX分析、可能不落地 | 3-4类 | 1-2周 |

```

    ↓否

```

## 二、场景一：0→1 新产品设计（12类产出）

### 调研阶段
1. **用户研究报告** — 目标用户画像、用户旅程地图、痛点与需求分析
2. **竞品UX分析报告** — 直接竞品+间接竞品的设计语言、交互模式、信息架构对比
3. **设计趋势与环境分析** — 行业设计规范（如iOS HIG/Material Design）、视觉风格趋势

### 规划阶段
4. **信息架构设计** — 站点地图/应用架构图、导航层级、内容分类体系
5. **Design Token定义** — 颜色体系(主色/辅色/中性/语义色)、字体体系(层级/行高/字重)、间距体系(4pt/8pt栅格)、圆角/阴影/动效参数
6. **组件库规划** — 原子设计方法论（Atoms→Molecules→Organisms→Templates→Pages）、组件清单与优先级、变体(variant)定义

### 设计阶段
7. **交互设计规范** — 全局交互模式（导航/返回/手势/键盘）、页面转场动画、反馈机制（Loading/Toast/确认弹窗）、错误状态处理
8. **高保真设计稿** — 关键页面(首页/核心流程/设置/空状态)、多端适配方案（iOS/Android/Web/小程序）
9. **可交互原型** — 核心流程可点击原型、用户测试用原型
10. **无障碍设计规范** — WCAG 2.1 AA标准、色对比度检查、屏幕阅读器适配、焦点管理、触控区域最小尺寸

### 落地阶段
11. **设计标注与交付规范** — 切图规范(@2x/@3x/矢量)、标注文档(间距/颜色/字体/状态)、组件命名规范、Figma/Sketch组织规范
12. **设计走查清单** — 开发还原度检查表、各端适配检查表、交互状态覆盖检查表(default/hover/active/disabled/error/empty/loading)

## 三、场景二：中大型功能迭代（6-8类产出）

1. **需求理解文档** — 功能背景、用户场景、业务目标
2. **交互流程图** — 用户操作路径、主流程+异常分支+边界条件、页面跳转关系
3. **线框图/低保真原型** — 页面布局、内容优先级、信息层级
4. **高保真Mockup** — 关键页面视觉稿、各状态覆盖
5. **交互说明文档** — 每个交互元素的输入/反馈/状态、动画参数、手势定义
6. **设计标注** — 颜色/字体/间距/组件标注
7. **变更影响范围分析** — 受影响的其他页面/组件、需同步更新的设计文档
8. **走查清单** — 还原度检查、多端适配、异常状态覆盖

---

## 四、场景三：小优化/微调（2-3类产出）

1. **问题描述与优化方案** — 当前问题(附截图)、优化目标、改动说明
2. **标注截图** — 修改前/修改后对比，具体改动标注(颜色值/间距值/字号等)
3. **变更记录** — 更新设计文件位置、通知相关开发

---

## 五、场景四：设计系统大版本升级（8-10类产出）

1. **升级评估报告** — 升级动机、现有系统痛点分析、升级目标与预期收益
2. **差异分析** — 新旧Design Token对照表、组件API Breaking Changes清单、视觉风格差异对比
3. **迁移方案** — 渐进式迁移策略(分模块/分阶段)、旧版兼容方案、并行运行方案
4. **新版Design Token文档** — 完整Token定义、命名规范、使用场景
5. **新版组件库文档** — 每个组件的API/变体/状态/用法、迁移指南(旧→新)
6. **视觉回归测试方案** — 截图对比流程、自动化测试配置、关键页面检查清单
7. **变更日志** — 完整的Breaking Change列表、废弃警告、迁移时间线
8. **团队培训材料** — Slide/录屏/FAQ、迁移Workshop计划
9. **存量项目升级计划** — 各项目升级优先级、依赖关系、排期
10. **走查清单** — 升级后验证、多端验证、性能回归

## 六、场景五：概念探索/预研（3-4类产出）

1. **探索背景文档** — 业务问题/机会描述、探索目标
2. **Mood Board（情绪板）** — 2-3套风格方向、配色/字体/质感参考、设计关键词
3. **概念方案** — 2-3个核心页面概念稿、可行性分析(技术/资源/时间)
4. **竞品UX分析** — 关键竞品的交互模式、视觉风格、优劣势对比

## 七、通用设计交付标准

### 设计稿规范
- 命名规范：`{模块}_{页面/组件}_{状态}_{版本}`，如 `Home_Banner_Default_v2`
- Figma组织：Pages（探索/设计稿/标注/组件库/归档）
- 版本管理：大版本用 `.v1/.v2`，小迭代用日期 `_240722`
- 组件化：相同元素必须做成Component，使用Auto Layout，使用Style/Token

### 标注要求
- 颜色：标注色值 + 使用场景（如 `#1A1A2E / Brand Primary`）
- 字体：标注字号 + 行高 + 字重 + 使用场景
- 间距：标注水平/垂直间距（相对父容器或相邻元素）
- 状态：每个交互元素覆盖 default / hover / active / disabled / error / empty / loading
- 适配：标注响应式断点、弹性布局规则

### 交互状态覆盖清单
每个交互元素必须覆盖且标注以下状态：

| 状态 | 说明 | 必须覆盖 |
|------|------|:--:|
| Default | 默认/初始状态 | ✅ |
| Hover | 鼠标悬停（Web/Desktop） | ✅ |
| Active/Pressed | 按下/点击中 | ✅ |
| Disabled | 不可用状态 | ✅ |
| Focus | 键盘焦点（无障碍） | ✅ |
| Error | 错误提示状态 | ✅ |
| Empty | 无数据/空内容 | ✅ |
| Loading | 加载中/骨架屏 | ✅ |
| Success | 操作成功反馈 | ✅ |

### 无障碍最低要求（WCAG 2.1 AA）
- 色对比度：正文 ≥ 4.5:1，大字 ≥ 3:1，UI组件 ≥ 3:1
- 触控区域：最小 44×44pt（iOS）/ 48×48dp（Android）
- 焦点管理：Tab键可遍历所有可交互元素
- 屏幕阅读器：图片有alt文本，表单有label，状态变化有announcement
- 不依赖颜色传达信息：错误状态同时使用图标+颜色+文本

### 设备适配标准
| 平台 | 最小支持 | 设计基准 |
|------|---------|---------|
| iOS | iPhone SE → Pro Max | iPhone 14/15 (390×844) |
| Android | 360dp → 414dp | 390dp (hdpi→xxxhdpi) |
| Web | 320px → 1920px | 375px(移动)/768px(平板)/1440px(桌面) |
| 小程序 | 微信/支付宝/抖音 | 375px |

- [ ] 情感节奏已映射：用户最焦虑的环节有对应的安抚设计

## 十、超越AI感：设计灵魂注入指南

> AI 能生成"结构正确"的设计，但只有真正的设计思考能产出"有灵魂"的设计。本节的每一条原则，都是为了把设计从"能用的工具"拔高到"让人想用的体验"。

### 10.1 反模板化十条

这十条是硬约束——每条都是一个 AI 设计的典型陷阱和对应的破局方法。

**1. 禁止完美对称**

AI 会本能地居中对齐、均匀分布。真实设计需要视觉张力。
- ❌ 所有元素居中、左右对称、等间距分布
- ✅ 60-30-10 视觉权重分布：60%主导区（英雄内容）、30%辅助区（导航/上下文）、10%留白区或意外元素
- 检查方法：截图后模糊处理，看视觉重量是否集中在 60% 区域

**2. 色彩要有立场**

AI 永远选择安全牌：蓝色主色 + 灰色中性 + 浅色点缀。但品牌不是安全牌。
- ❌ #2563EB 蓝 + #6B7280 灰 + #10B981 绿点缀（这是"AI默认配色"）
- ✅ 每个颜色选择必须回答：**为什么是这个颜色，而不是旁边那个**
- 使用"色彩立场声明"：`主色 #XX → 传达[品牌关键词] → 替代色 #YY 为什么不行：[理由]`
- 技巧：先选一个"不该用"的颜色，再选对的那个——对比让你更清楚选择理由

**3. 字体配对要有戏剧性**

AI 默认 Heading + Body 都用无衬线，字体层级是数学题，不是音乐。
- ❌ Inter 全家桶（标题 Inter Bold + 正文 Inter Regular）
- ✅ 制造对比：衬线标题 + 无衬线正文 / 窄体标题 + 常规正文 / 极粗标题 + 纤细正文
- 字体层级应该有**节奏感**：像音乐有强拍弱拍，标题字距收紧、正文字距放松
- 不少于 2 个字族，不超过 3 个

**4. 负空间是设计的第一元素**

AI 倾向于填满空间。但高端感=呼吸感。
- 奢侈品：留白占 40%+ 面积
- 工具类：留白 20-30%
- 信息密集型：留白至少 10%，且集中在关键信息周围
- 规则：**每个模块周围的最小间距 = 该模块内最大字号的 2 倍**

**5. 打破栅格才有记忆点**

遵循栅格是基本功，打破栅格是设计力。
- 90% 严格遵循栅格 + 10% 有意打破 = 有灵魂的布局
- 打破方式：Hero 图片出界 10%、CTA 按钮悬浮在分区线上、标题偏移造成视觉张力
- 原则：打破栅格的元素必须是页面最重要的那个元素——不是随便打破，而是为了强调

**6. 微交互决定品质感**

AI 能描述状态（default/hover/active），但描述不了"质感"。
- 每个微交互定义三个参数：**时长**（ms）、**缓动曲线**（cubic-bezier 具体值）、**性格**（弹性/沉稳/锐利）
- 按钮 hover：不是简单的颜色变深，而是 200ms + ease-out + scale(1.02) + 阴影从 2px 升到 4px
- 页面转场：品牌调性决定动画性格——金融类用无动画（稳）、社交类用弹性动画（活泼）、工具类用 fade（高效）

**7. 为极端内容设计，不为理想内容设计**

AI 用完美的 placeholder 设计。真实世界内容永远是混乱的。
- 每个文本区域设计 3 个版本：最短（2-3 字标题）、典型（8-15 字）、最长（30+ 字折行）
- 数字格式：金额 `¥10,000.00` vs `¥9.90`、手机号脱敏 `138****1234`、中文地址完整链
- 图片测试：横向图、纵向图、正方形图、无图——每种情况布局都不能崩

**8. 文化语境决定设计语法**

中文 UI 不是英文 UI 的翻译版。
- 中文阅读模式：Z 字形扫描（先横后纵），英文是 F 形——信息层级排列逻辑完全不同
- 中文字号至少比英文大 1-2px 才等感知大小（中文笔画密度高）
- 颜色文化含义：红色=喜庆/促销/警示（不像西方=danger）、白色=哀悼（不像西方=purity）
- 数字敏感：中国人对 8（发）、6（顺）、4（死）敏感——价格尾数、数量都用 8/6 收尾

**9. 品牌是每像素的偏执**

遮住 logo，这个设计还能被认出是哪个品牌吗？不能？那就还不是品牌设计。
- 品牌性格必须可以拆解为像素级参数：圆角半径、阴影深度、色温偏移、字间距偏好
- 设计完成后做"logo 遮盖测试"：截图→涂掉 logo→给陌生人看→能说出品牌调性算通过
- 如果从 Apple 换成麦当劳，这个设计的哪些像素需要变？如果答案是"什么都不用变"，那这就是 AI 设计

**10. 不完美才是人性证据**

AI 产出过于干净。真实设计有"手感的痕迹"。
- 允许：插图笔触不完美、配色有意偏暖/偏冷几个点、圆角不是纯数学圆（微调 1-2px）
- 纹理感：浅色背景叠加 2-5% 噪点、纸张纹理、微妙的渐变而非纯色
- 字体微调：标题字距手动收紧 -2% 到 -5%，正文不做任何机械计算

### 10.2 品牌气质矩阵

将抽象的"品牌调性"词汇翻译为具体的像素级设计参数。

| 品牌气质 | 圆角 | 阴影 | 字重偏好 | 色温 | 间距风格 | 动效性格 | 代表品牌 |
|---------|------|------|---------|------|---------|---------|---------|
| 专业/权威 | 2-4px | 硬阴影 rgba(0,0,0,0.08-0.12) | 600-700 | 冷色偏蓝 5-10° | 紧凑 8-12px | 无或瞬间 | 招商银行/IBM |
| 年轻/活力 | 12-24px | 彩色投影 rgba(主色,0.15-0.3) | 400-500 | 暖色偏橙 15-25° | 宽松 16-24px | 弹性 spring | 小红书/B站 |
| 奢华/高端 | 0-2px | 无或极淡 | 200-400 细体 | 中性偏暖 0-5° | 极大 32-56px | 缓慢 fade(>400ms) | 蔚来/Apple |
| 温暖/亲切 | 8-16px | 柔阴影 rgba(暖色,0.08-0.15) | 400-500 | 暖色明显 20-30° | 舒适 12-20px | 柔和 ease-in-out | 微信/自如 |
| 科技/未来 | 4-8px | 发光 or 渐变阴影 | 300-600 变化大 | 冷色偏紫 -15~-30° | 中等 12-16px | 科技感 glitch/shine | Notion/Midjourney |
| 极简/克制 | 0-4px | 无 | 300-400 | 完全中性 0° | 极大 40-80px | 无 | MUJI/Linear |

使用方法：
1. 从矩阵中选择 1-2 个最匹配品牌的气质标签
2. 将对应列的参数作为设计的"硬约束范围"
3. 任何超出范围的参数选择，必须写理由
4. 用不同品牌气质做同一界面 → 对比 → 选出最像自己品牌的那个

**品牌一票否决测试**：找 3 个不相关的路人，遮住 logo 给他们看设计 → 问「这个产品给人什么感觉」→ 至少 2 人能说出品牌关键词才算通过。

### 10.3 视觉张力语言

**焦点法则**
- 每个页面/屏幕必须有且仅有 1 个视觉焦点——第一眼必然落在那
- 焦点元素占画面 20-30% 面积，其余内容退后到"第二眼才会看"的位置
- 制造焦点的手法：尺寸（最大/最小）、颜色（最鲜艳/最淡）、位置（偏左/偏右而非居中）、形状（唯一异形）

**节奏交替**
- 长滚动页面：内容密度交替——密→疏→密→疏，像呼吸一样有节奏
- 组件排列：避免"一排 3 个重复卡片"——改用 2+1、大+小、横+纵的组合
- 色彩节奏：每屏有一个"突变色"（和整体色调形成 60°+ 色相差），其他区域为调和色

**意外元素**
每 3-5 屏（或关键页面）插入一个用户"没想到但很舒服"的元素：
- 打破预期的排版角度（非 0°/90° 的微妙倾斜）
- 超出容器的视觉元素（人物/产品图破出卡片）
- 过渡动画中的趣味帧（loading 不是转圈，是品牌相关的小动画）

### 10.4 情感节奏设计

只画用户流程图是不够的。每个流程节点，用户有情绪——设计要对情绪做出回应。

| 用户阶段 | 功能节点 | 用户情绪 | 核心设计策略 | 反面案例（AI会犯的错） |
|---------|---------|---------|------------|---------------------|
| 初识 | 首页/Landing | 好奇+怀疑 | 3秒传达价值主张，视觉冲击先于信息 | 堆砌功能列表，像产品说明书 |
| 探索 | 浏览/搜索/分类 | 期待+轻微焦虑 | 即时反馈(<100ms)、降低选择成本 | 空结果页只写"暂无数据" |
| 决策 | 详情/对比/评价 | 犹豫+计算 | 社会证明（销量/评价）、风险消除（退换政策） | 纯参数列表，无情感锚点 |
| 行动 | 下单/支付/提交 | 紧张+兴奋 | 确认感设计、防误操作、进度可见 | 只有一个"提交"按钮，无二次确认 |
| 等待 | 加载/处理中 | 焦急+无聊 | 进度可见+剩余时间+趣味消解 | 转圈 spinner 转 10 秒 |
| 完成 | 成功/确认页 | 满足+成就感 | 仪式感（动画/音效/徽章）、下一步引导 | 仅"操作成功"三字 |
| 异常 | 错误/失败/404 | 沮丧+想放弃 | 共情文案先行、清晰出路在后、保留已输入内容 | "系统错误，请稍后重试" |

**情绪应对设计三原则**：
1. **先共情再解决**：错误页先说"哎呀，好像出了点问题"而不是"Error 500"
2. **给出口不给死路**：404 页必有搜索框+热门链接，不是只剩"返回首页"
3. **帮用户保住劳动成果**：表单校验失败保留已填内容，支付失败自动暂存订单

### 10.5 真实内容思维

**中文真实内容设计检查**
- 标题：3字短标题 / 15字中等 / 30字长标题折行——三种都测
- 正文：200字段落（短）/ 800字段落（长）/ 0字（无内容）——三种状态
- 数字：`¥9.90`（最小） / `¥9,999.00`（典型） / `¥999,999.00`（极限）
- 手机号：`138****1234`（脱敏标准格式）
- 地址：`广东省深圳市南山区科技园南路XX大厦A座1806室`（完整链，折行测试）
- 时间：`刚刚` / `3分钟前` / `昨天 14:30` / `2025年3月15日`（四种粒度）

**空状态不是空白，是入口**
- 列表为空 → 不是"暂无数据"，而是"创建第一条XX" + 引导按钮 + 示例
- 搜索无结果 → 不是"未找到"，而是"试试这些关键词" + 热门推荐
- 新用户首页 → 不是空白仪表盘，而是"3步完成设置"向导
- 规则：**每个空状态必须包含一个行动号召（CTA）**

### 10.6 行业精度：不同赛道的设计母题

不同行业有不同的"设计坐标系"——跨行业套模板是 AI 味的最大来源。

| 行业 | 设计母题 | 关键约束 | AI易犯错误 |
|------|---------|---------|-----------|
| 电商 | 商品即内容 | 图>文、价格显眼、行动按钮大 | 把商品当文章排版 |
| 金融 | 信任感即产品 | 数字精确（两位小数）、操作可撤销、无歧义 | 用活泼配色/动画 |
| 社交 | 人的面孔优先 | 头像>昵称>内容、无限滚动、低延迟 | 卡片式排布，缺乏亲密感 |
| 工具/SaaS | 效率即体验 | 信息密度高、操作路径短、快捷键 | 过度留白浪费空间 |
| 内容/媒体 | 阅读体验至上 | 排版呼吸感、夜间模式、字号可调 | 广告位干扰阅读流 |
| 医疗/健康 | 准确+安抚 | 专业感配色（蓝/白/绿）、大字号、少动效 | 花哨动效，缺乏专业感 |
| 教育 | 进度可见性 | 坚持天数、完成百分比、成就系统 | 只做内容展示，不做激励 |
| 企业/B2B | 角色即界面 | 多角色视图、权限可视化、审批流 | 用C端审美做B端设计 |

**行业适配检查**：在产出任何设计方案前，先回答——「这个行业的设计母题是什么？我的方案有没有踩到这个母题的核心？」
